# Lessons

- Do not keep `async-trait` in this repo unless a trait needs dynamic dispatch. Prefer native trait futures for static dispatch, using explicit `impl Future + Send` return types for public traits.
- For any failed gate, inspect the failing test and its fixture path before classifying it as a flake. Isolation reruns are evidence, not root-cause analysis.
- In code review, do not downgrade a semantic gap between spec and implementation to "non-blocking" just because the test suite passes. Tests not covering a failure mode is not evidence the failure mode is acceptable. Shutdown ordering and swallowed error results are exactly what tests miss until production — flag them as potential blockers.
- Before suggesting a rollback or error-path change in a transaction, verify what has actually been written into the transaction at the point of failure. Suggesting a rollback on an empty transaction introduces a defect, not a fix.
- A defect that is benign at today's scale is not automatically cosmetic. Evaluate how it compounds as components multiply (N services, N call sites), and treat an unenforced cross-component convention as a latent risk to resolve structurally. Runtime-port example: the old in-process `Runtime(String)` versus wire `Client(ClientError)` provenance split is now enforced by `lilo-port`: `PortError` has caller-matched `Fault` plus opaque provenance, and `ParityProof` forces dual-adapter conformance arms for every `RuntimeFault`. See `~/.mdx/projects/littleorgans-bounded-context-port-error-model--design.md`.
- In pre-release littleorgans protocol work, do not add legacy fallback constants, aliases, or compatibility vocabulary. Breaking changes are expected when they simplify the design.
- For selector driven mail send, treat only `RUNNING` sessions as actionable recipients before authz, persistence, or notify. Stale terminated matches are not delivery attempts.
- Default human session lists should stay compact for operator scanning. Keep deep fields like directory, pid, and timestamps in JSON unless the user asks for them in the table.
- Operator mail observability needs a discovery path for `context_id` values. A transcript filter is not enough if the operator cannot first list conversations and counts.
- Mail `--notify` nudges must be wake cues, not copies of the durable mail body. The recipient should see a small mail notification and read the actual content from the mailbox.
- Before making any change — a text tweak, a one-line edit, or a new function — apply human engineering judgment to the wider context, not just the local diff. Ask: is it consistent with surrounding conventions (casing, naming, structure, patterns)? Is it DRY — does an equivalent helper/type/constant already exist (search before adding; reuse or refactor so callers share one path)? Where is the best home for new code (cohesion, navigability)? What is the blast radius — even a one-liner can ripple through callers, generated surfaces, or contracts? Is this a chance to refactor toward something cleaner and easier to navigate? Emulate what a competent human does before touching code. A request to make a change is not permission to skip this thinking; the only exception is an explicit "do exactly this, don't think." (The `Global Options` vs sentence-case `Session commands` casing slip was one symptom of skipping the consistency pass.)
- When deleting a feature, env var, flag, or code path, do not add a standing test that asserts it stays gone (no-effect / still-removed guards). Deletion is proven once by the diff and a green suite; a perpetual deletion guard is negative-value coverage, often a tautology, and it keeps the dead name alive in the tree — defeating the deletion and the no-legacy rule above. Tests assert what the system does now. Different in kind and fine: live `must-not` invariants (input must not override a verified token) and namespace lints that enforce one rule across all names (e.g. `check-env.sh` rejecting `RTM_/SM_/AGM_`). This applies to removed CLI flags and MCP params too: assert the replacement behavior parses and works, not that the removed spelling still fails. Concrete miss caught in env-var work: `lilo_log_json_env_var_has_no_format_effect` `set_var`'d two phantom env vars then called `select_format`, a pure helper that never reads env — a tautology guarding names that were never live.
- For short-id UX docs and examples, do not teach the absolute minimum accepted selector prefix when the operator mental model is Git-style short display. Use the 7-character human display floor in examples, and reserve the 4-character floor for parser and store validation.
